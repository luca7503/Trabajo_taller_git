¿que es github?

Para poder entender que es github lo vamos a relacionar con un servidor de minecraft. Es decir un mundo donde varias personas pueden interactuar con el lugar(construir, romper, etc...), a diferencia del singleplayer donde uno esta solo.
Lo mismo pasa con git y github. Git es la herramienta con la que podes guardar tu codigo (mundo) y github (el server) es donde podes subir el codigo para compartir codigo, colaborar en el mismo proyecto, tener una copia del proyecto remota, etc...

Comandos relacionados con github

En esta parte vas a poder encontrar todos los comandos relazionados a github con una explaciacion de que hace y para q sirven. (Los comandos basicos de git fueron explicados en la seccion de git)

  • Git clone

    Este comando sirve para clonar/copiar un repositorio de GitHub. Es decir, después de usar este comando se va a crear una carpeta con el nombre del repositorio que se esté queriendo copiar en tu computadora, y va a tener dicho código también. En términos minecrafteanos sería el equivalente de copiar un mundo de Minecraft porque te gustó y/o querés cambiarle algo.
    La estructura de este comando es la siguiente git clone ""; entre comillas se ubicaría la URL del repositorio que se quiera copiar.

  • git remote add origin

    Este comando tiene un objetivo bastante similar al git clone. Solo que este, en vez de traer un repositorio que ya existe, te permite vincularte con un repositorio tuyo y subir tu código. Para que se entienda de forma más sencilla, vos tenés tu mundo de Minecraft y con este comando lo podés subir a un server para que otras personas lo puedan ver, copiar, modificar o hacer lo que vos les permitas con tu mundo.
    La estructura de este comando es así: git remote add origin "". Entre comillas también debe ir la URL, ya que se necesita vincular con el repositorio.

  • Git pull

    Este comando permite actualizar tu versión del código. En otras palabras, si el código que clonaste se actualiza y querés tener los cambios, deberías usar este comando para poder obtenerlos. Pensándolo en Minecraft, es como si ese mismo mundo que copiaste porque, por ejemplo, tenía un castillo re bueno, al día siguiente recibe una ciudad y querés tener esa ciudad en tu versión también.
    Este comando tiene la estructura de git pull y no hace falta poner nada más si el repositorio remoto ya está configurado.

  • Git push

    Este comando sería el inverso del git pull; es decir que, en vez de traer cambios, sirve para subirlos. Básicamente, permite actualizar el repositorio remoto con los cambios que hicieras en el local. Volviendo a la analogía de Minecraft, vos cambiaste el castillo para que, en vez de tener una apariencia similar a la de los castillos persas, se vea más como un castillo teutón, y ahora querés subir ese cambio.
    Este comando tiene la sintaxis de git push. En su forma básica, tampoco necesita una URL si el repositorio remoto ya está configurado.

  • Git fetch

    Este comando es muy similar al git pull, con la diferencia de que no integra automáticamente los cambios en tu rama actual. Es decir, te deja ver los cambios y después decidir si querés incorporarlos o no. Hablando en Minecraft, lo que estás haciendo es ver el mundo actualizado por un lado mientras todavía tenés el propio por el otro, permitiendo así compararlos antes de decidir.
    Este comando se realiza con git fetch y, al igual que el pull, no necesita una URL si el repositorio remoto ya está configurado.

  • Pull request

    Más que un comando, esto es una aclaración. Si la persona dueña del repositorio no te permite subir cambios directamente, podés proponer tus modificaciones mediante una pull request. El dueño podrá revisar los cambios y decidir si los acepta o no. En un repositorio propio, normalmente podés realizar cambios directamente si tenés los permisos necesarios.
    En terminología minecrafteana, si el servidor es de otra persona, sería como construir algo en tu propia copia del mundo y pedirle al dueño que incorpore tu construcción al mundo original.

Como trabajar en un repositorio ajeno

Para poder trabajr en un repo ajeno hay 2 formas. La primera es que te inviten como colaborar, en cuyo caso vas a poder trabajar como si fuera un repositorio propio. El otro medio es copiando el repositorio y despues de hacer cualquier cambio que veas pertinente podes solicitar un push el cual permite al dueño del repo ver los cambios que estas propniendo y si le parecen optimos los va aceptar y subir su repositorio.
Viendolo nuevamente de forma minecrafteana esto es el equivalente de pedirle permiso a una persona para entrar a su server. En caso de que te den permiso vas a poder entrar y construir, romper y basicamente interactuar con su mundo

Como crear un repositorio

Para crear y configurar un repositorio en github es muy facil. Asumiendo que ya vinculaste tu cuenta github y git (pasos explicados en la seccion de git) Lo que vas a tener que hacer ahora es ir a github y crear un repositorio (en la parte de repositorios, se toca el boton de crear nuevo repositorio), ahi pueden ponerle nombre, descripcion, hacerlo publico/privado, agregarle licensia al codigo, crearlo con un archivo de texto (para poner alguna informacion extra sobre el proyecto que concideres relevante) y poco mas. Ya con eso estaria creado, ahora hay que vincular el repositorio de github con una carpeta git (ya sea que ya este trabajda o una nueva para empezar de 0). Ya habiendo explicado en la seccion de git como iniciar un proyecto ahora viene como vincularlo a github. Para eso hace falta el "git remote add" que meniconamos antes. Una vez hecho eso el repositorio del cual hayas sacado la url y el proyecto en el cual ejecutaste este comando ya van a estar vinculados. A partir de ahi cada vez que quieras subir un cambio solo tenes que seguir los pasos de la seccion git para realizar un commit y pushear a tu repositorio.
Para que se entinda un poco que es lo que se esta haciendo. Creando un repositorio lo que hacemos es preparar un server para subir nuestro mundo, ahi a la vez estamos eligiendo si queremos que nuestro mundo sea publico para que todos pueda unirse, copiarlo, etc... o no. Despues vinculamos el server con el mundo que ya tenemos preparado y ahi si ya esta publicado.
